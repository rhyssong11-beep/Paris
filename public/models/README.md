# 3D 모델 파일

랜드마크 3D 뷰어가 불러오는 파일을 이 폴더에 둡니다. 뷰어는 아래 순서로 찾아서 처음 발견한 것을 보여줍니다.

1. **가우시안 스플랫** (실제 사진으로 만든 실사 장면) — `eiffel.spz`, `eiffel.sog`, `eiffel.ksplat`, `eiffel.splat`, `eiffel.ply` 순서
2. **GLB 모델** — `eiffel.glb`
3. 둘 다 없으면 코드로 만든 임시 모델

| 파일 이름 (확장자 제외) | 랜드마크 |
|---|---|
| `eiffel` | Tour Eiffel |
| `louvre` | Musée du Louvre (`louvre.glb`, `npm run model:louvre`로 생성. 미터 단위 그대로 사용되므로 크기 자동 맞춤 없음. 궁전은 외벽 한 칸·굴뚝·파빌리옹 모듈을 GPU 인스턴싱으로 반복 배치하며, `louvre/` 폴더의 PNG 텍스처 4장을 뷰어가 재료 이름으로 찾아 입힘) |
| `arc` | Arc de Triomphe (`arc.glb`, `npm run model:arc`로 생성. 미터 단위 그대로 사용하며 개선문·에투알 광장·12개 방사형 대로·내부 옥상 계단 포함) |
| `notredame` | Notre-Dame (`notredame.glb`, `npm run model:notredame`로 생성. 미터 단위 그대로 사용. 원본은 Higgsfield 3D Jutsu 프로젝트의 GLB 내보내기(`scripts/notredame/jutsu-export.glb`)이며, `notredame/` 폴더의 WebP 텍스처 8장을 뷰어가 재료 이름으로 찾아 입힘) |

## 가우시안 스플랫 파일 조건

- **형식**: `.spz`, `.sog`, `.ksplat`, `.splat`, `.ply`(3DGS 표준 또는 압축 PLY) 중 하나.
- **용량**: GitHub는 100 MB를 넘는 파일을 거부합니다. 가능하면 50 MB 이하로, 큰 `.ply`는 압축 형식(`.spz`, `.sog`, 압축 PLY)으로 변환하세요. 클수록 처음 열 때 오래 걸립니다.
- **라이선스**: 재배포가 허용된 것(CC0, CC BY 등). CC BY라면 `src/viewer-registry.ts`의 `credit`에 제작자와 출처를 적어야 합니다.
- **범위**: 에펠탑이 장면의 중심에 있고 주변이 너무 넓지 않은 것이 좋습니다. 뷰어는 장면의 높이를 탑 높이에 맞추고 바닥 중앙에 세웁니다.

방향이 뒤집혀 보이거나 크기·위치가 어긋나면 `src/viewer-registry.ts`의 `splat` 항목에서 조정합니다.

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `rotation` | x, y, z축 회전(도) | `[180, 0, 0]` (대부분의 촬영 데이터는 위아래가 뒤집혀 있음) |
| `scale` | 장면 단위 1을 몇 미터로 볼지 | 장면 높이를 탑 높이에 자동 맞춤 |
| `offset` | 중앙 정렬 후 옮길 거리(미터) | `[0, 0, 0]` |
| `background` | 배경색 | `#0b0e14` |

스플랫은 촬영 당시의 빛이 색에 그대로 들어 있어서, 이 모드에서는 낮/밤 전환과 조명 효과가 없습니다.

## GLB 모델 파일 조건

- **형식**: glTF 바이너리(`.glb`) 한 개. 텍스처가 파일 안에 포함된 것. Draco·Meshopt 압축 지원.
- **용량**: 30 MB 이하 권장.
- 크기·방향·위치는 뷰어가 자동으로 맞춥니다 (높이를 실제 높이로 맞추고 바닥 중앙에 세움).
- 현재 들어 있는 `eiffel.glb`는 `npm run model:eiffel`로 생성한 파일입니다.

## 포함된 에펠탑 모델

- 약 **1.31 MB**, Meshopt 압축·좌표 양자화 적용. 재생성하려면 개발 의존성까지 설치해야 합니다.
- 1층은 중앙이 열린 고리형 바닥과 유리 바닥 띠로 구성하고, 창유리와 창틀을 분리했습니다. 2층과 정상 전망대도 두꺼운 덩어리를 줄였습니다.
- 정원과 두 연못은 공식 현장 안내를 참고한 근사 배치입니다. 주변 도시·강·샹드마르스는 뷰어가 생성하는 배경이며 실제 지적도와 일치하지 않습니다.
- 밤에는 황금빛 조명을 기본으로 표시합니다. ‘반짝임 보기’는 30초 미리보기이며 실제 정시 공연 시간표와 연동되지 않습니다.
- 가까이서 보는 높음/균형 화질에서는 보조 철골을 표시하고, 멀리 보거나 절약 화질일 때는 생략합니다. 주요 기둥과 대각 가새는 유지합니다.

## 노트르담 모델과 텍스처

- 모델은 약 **3.5 MB**, 삼각형 약 17.7만 개, 재료 16개입니다. 노드 이름은 `NotreDame_<재료>`입니다.
- `notredame/` 폴더의 텍스처는 Higgsfield 이미지 생성(GPT Image 2.6)으로 만든 것입니다. 같은 이름의 WebP로 바꿔 넣으면 그대로 적용됩니다.

| 파일 | 입히는 곳 | 비고 |
|---|---|---|
| `rose-west.webp`, `rose-north.webp`, `rose-south.webp` | 서쪽·북쪽·남쪽 장미창 | 정사각형, 원이 네 변에 닿게. 밤에는 발광 맵으로도 사용 |
| `lancet.webp` | 첨두 창 유리 전체 | 세로형, 첨두 아치가 화면을 꽉 채우게 |
| `tympanum.webp` | 정문 다섯 곳의 팀파눔 | 정사각형, 첨두 아치 모양 |
| `door.webp` | 정문 문짝 | 세로형 한 짝(반대쪽은 좌우 반전) |
| `ashlar.webp` | 석재 벽면 | 4 m마다 거울 반복 |
| `lead.webp` | 지붕과 첨탑의 납판 | 4 m마다 거울 반복 |

- 텍스처를 불러오지 못하면 재료의 단색으로 표시됩니다.
- 성당 내부는 만들지 않았습니다. 실제 축은 정동에서 남쪽으로 조금 틀어져 있지만 모델과 주변은 축에 맞춰 직각으로 배치했습니다.

## 루브르 모델과 텍스처

- 모델은 약 **2.7 MB**입니다. 저장된 삼각형은 약 11.5만 개이고, 모듈을 반복해 그리는 삼각형은 약 168만 개입니다.
- 모듈의 정점 색에는 주변에 얼마나 가려지는지(창 안쪽, 코니스 밑, 벽 아래)를 광선으로 계산해 구워 넣었습니다(`scripts/louvre/bvh.mjs`).
- 피라미드 아래에는 나폴레옹 홀(격자 천장, 메자닌, 나선 계단과 원형 승강 플랫폼)이 있고, 안쪽 안뜰은 유리 지붕으로 덮었습니다. 치수는 근사값입니다.
- 궁전은 `scripts/louvre/palace.mjs`가 만드는 모듈 여섯 개(`Palace_Bay_A`, `Palace_Bay_B`, `Palace_Chimney`, `Palace_Pavilion`, `Palace_Pavilion_Low`, `Palace_Clock`)로 이루어집니다. 외벽 한 칸에는 3층 창과 창살, 기둥, 코니스, 난간, 맨사드 지붕 절반, 도머 창이 들어 있습니다.
- `louvre/` 폴더의 텍스처(`stone.png`, `trim.png`, `slate.png`, `lead.png`)는 `scripts/louvre/textures.mjs`가 코드로 만든 것입니다. 이어 붙일 수 있는 무늬이고, 모델의 UV는 몇 미터 단위로 반복됩니다.
- 실제 궁전의 축은 조금 틀어져 있지만 모델은 동서 축에 맞춰 직각으로 배치했습니다. 파빌리옹은 높은 돔과 낮은 지붕 두 가지 모듈을 돌려 쓰고, 조각은 덩어리로 줄였습니다.
